# Report definitions

> Educational demo on synthetic data. Thresholds and code lists are illustrative, not clinical
> guidelines. Review any real use with a clinician and a data steward.

All reports take the report date as `:as_of` (default today, set with `--as-of`). Results dated
after `:as_of` are ignored, so a past date reproduces what the report would have said then.
Dates are compared as `YYYY-MM-DD` text (timestamps are truncated on load).

## diabetes_cohort: HbA1c control

**Question.** Among patients with active diabetes, who has a recent HbA1c and is it in control?

**Cohort.** A condition with SNOMED code 44054006, 46635009 or 73211009 that started on or before
the report date and has no end date (or an end date after it).

**Measure.** The most recent HbA1c (LOINC 4548-4) on or before the report date.

| Status | Rule |
|---|---|
| No recent test | no HbA1c, or the latest is older than `window_days` (default 365) |
| In control (<7) | latest value below 7 |
| Above goal (7 to <9) | 7 or higher and below 9 (exactly 7.0 lands here) |
| Poor control (>=9) | 9 or higher (exactly 9.0 lands here) |

**Parameter.** `window_days` (default 365).

**Limitations.** One fixed set of thresholds for everyone; real targets are individualised. Only
the latest value is used, not a trend. A result recorded in another system is invisible here.

## medication_safety: metformin without a recent renal function test

**Question.** Which patients on active metformin have no creatinine or eGFR in the lookback window?

**Cohort.** A medication with RxNorm code 861007, 860975 or 861004 that started on or before the
report date and has not stopped. A diabetes diagnosis is **not** required.

**Flag.** No creatinine (LOINC 2160-0) or eGFR (LOINC 62238-1, 33914-3) on or before the report
date within `window_days` (default 365). Patients with no test at all are listed first, then by
days since the last test.

**Limitations.** Illustrative monitoring rule. Ignores dose, kidney disease stage and contra-
indications. Tests done elsewhere will make a patient look unmonitored.

## noshow_summary: appointments by month

**Question.** How many scheduled appointments were fulfilled, missed or cancelled each month?

**Measure.** Count by status per calendar month over the last `months` (default 12) *complete*
months before the report date's month (as of 2026-11-15 with `months=12`: 2025-11 to 2026-10), so
no month is partial. `noshow_rate_pct` = no-shows / all scheduled (cancelled appointments stay in the
denominator).

**Limitations.** Synthea has no scheduling data. The `appointments` table is a synthetic extension
generated by `report-kit generate-data` (columns `Id, DATE, PATIENT, DEPARTMENT, STATUS`).

## Writing your own

Create `my_report.sql` with a header, then run it with `--reports-dir`:

```sql
-- title: Patients by decade of birth
-- question: How is the cohort distributed by birth decade?
-- key: decade
-- requires: patients
SELECT substr(birthdate, 1, 3) || '0s' AS decade, COUNT(*) AS patients
FROM patients GROUP BY 1 ORDER BY 1;
```

Header lines: `title`, `question`, `key` (a column that uniquely identifies each row, used for the
change diff) are required. Optional: `requires` (tables), `summary` (a column to count in the
Summary sheet), `limitations`, `diff_ignore` (comma-separated columns the change diff should
ignore, e.g. `age, days_since_test`, which move every day by themselves), and `param name: default`
for each extra parameter.

The key column is checked on every run: if it is missing or not unique the run stops with an
error. A parameter whose default is a whole number only accepts whole numbers >= 0, and
`--param` names that no selected report declares are rejected, so a typo can't fall back to the
default silently.
